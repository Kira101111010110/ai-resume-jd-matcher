# งานรอบ 3: อัปเดต exe ให้ตรงกับ AI เวอร์ชันล่าสุด + ทำให้อาจารย์ใช้งานง่ายที่สุด

## บริบท
- repo: https://github.com/Kira101111010110/ai-resume-jd-matcher (branch `main`)
- ผู้ใช้จริง: อาจารย์ที่ปรึกษา ใช้ในรายวิชา บน Windows ของอาจารย์เอง
- อาจารย์ตอบว่า "ยังไงก็ได้ให้ผมใช้งานง่ายสุด" → ส่งเป็น**โปรแกรมติดตั้ง + หน้าเว็บในเครื่อง** ไม่ใช่ script/CLI

  - ตั้งค่าครั้งเดียว (ใส่ API key + เลือกโมเดล) แล้วใช้ได้เลย

  [หมายเหตุ: ถ้าผู้ใช้บอกว่าอาจารย์จะใช้ผ่านเว็บเป็นหลัก ให้กลับไปเปิดส่วน ngrok เป็นค่าเริ่มต้นแทน]

## 0. ก่อนเริ่ม (สำคัญที่สุด)
1. หาว่างานรอบ 1–2 อยู่ที่ไหน (โฟลเดอร์นี้หรือโฟลเดอร์อื่น, commit แล้วหรือยัง) — ถามผู้ใช้ถ้าไม่แน่ใจ
2. สำรองก่อนแตะอะไร: commit งานในเครื่องลง branch ใหม่ (เช่น `exe-local-ui`) หรือ copy ทั้งโฟลเดอร์เก็บไว้
3. `git fetch` แล้ว merge `origin/main` เข้า branch นั้น
   - ไฟล์ที่น่าจะชนกัน: `app.py`, `launcher.py`, `llm_providers.py`, `pdf_extraction.py`, `requirements.txt`, `README.md`
   - ต้องเก็บของทั้งสองฝั่ง: endpoint/settings/tunnel จากในเครื่อง + visual skill/overlap fix จาก `main`
   - ห้ามแก้ conflict ด้วยการเลือกทั้งไฟล์จากฝั่งเดียว
4. **สรุปให้ผู้ใช้ดูก่อนลงมือ:** ไฟล์ที่ชน + วิธีที่จะรวม + รายชื่อไฟล์ที่จะสร้าง/แก้ในรอบนี้ แล้วรอยืนยัน
5. ห้ามทำให้ของเดิมเสีย:
   - contract ของ `/analyze` ที่ backend Node.js ใช้ (request/response เดิมต้องใช้ได้เหมือนเดิม)
   - การรันแบบ Docker / Hugging Face (`Dockerfile`, `uvicorn app:app --host 0.0.0.0`)

## 1. รวมฟีเจอร์ใหม่ของ AI เข้ากับ exe
- `/analyze-file` และหน้าวิเคราะห์ในเครื่อง ต้องสกัดข้อความผ่าน `extract_text_from_pdf_bytes()` ตัวเดียวกับ `resume_url` (ฟีเจอร์อ่านสกิลจากกราฟิกจะทำงานด้วยอัตโนมัติ) ห้าม copy logic ซ้ำ
- ชื่อ field ของคณะ/สาขาที่รับคือ **`faculty_match`** (ใน `AnalyzeRequest`) ไม่ใช่ `faculty` — เช็คว่า `/analyze-file` และฟอร์มในหน้าเว็บใช้ชื่อนี้ (spec รอบ 1 เขียนว่า `faculty` ซึ่งผิด)
- หน้าผลลัพธ์แสดง `visual_skills` เป็นป้ายแยก (เช่น "อ่านจากกราฟิก") ถ้า `visual_skills_used` เป็น true
- หน้าตั้งค่าเพิ่มส่วน **"อ่านสกิลจากกราฟิกในเรซูเม่"**:
  - สวิตช์เปิด/ปิด → เก็บใน `config.json` แล้วอัปเดต `os.environ["VISUAL_SKILL_EXTRACTION"]` ทันที (pdf_extraction อ่านค่าสดทุก request อยู่แล้ว)
  - ฟีเจอร์นี้ใช้ Gemini เสมอ ไม่ว่าเลือก provider ไหน — ถ้าเปิดไว้แต่ไม่มี Gemini key ให้ขึ้นข้อความอธิบายในหน้าตั้งค่าและหน้าผลลัพธ์ (backend ข้ามขั้นนี้ไปเองอยู่แล้ว ไม่ error)
  - โมเดล vision = โมเดล Gemini ที่เลือกไว้ในหน้าตั้งค่า (ตั้ง `VISION_MODEL_NAME` ตามนั้น) แทนการ hardcode `gemini-3.6-flash`
- `AnalyzeRequest.model_provider` ตอนนี้ default เป็น `"gemini"` → เปลี่ยนเป็น `None` แล้วเลือกตามลำดับ:
  1. ค่าที่ส่งมาใน request
  2. active provider ใน `config.json`
  3. `"gemini"` (กรณีไม่มี `config.json` เช่นตอนรันบน Docker)

## 2. บั๊กใน `main` ที่ทำให้ exe พังบนเครื่องอื่น (เช็คในเวอร์ชันที่ merge แล้ว ถ้ายังอยู่ให้แก้)
- **path โมเดลเป็น relative**: `test_full_pipeline_v4.py` โหลด `./resume-jd-matcher-model/resume-jd-matcher` และ `./skill-extractor-model` ตรงๆ (comment ใน `launcher.py` บอกว่าใช้ `resource_path()` แล้ว แต่จริงๆ ยังไม่ได้ใช้) → เปิดจากไอคอนบนเดสก์ท็อปที่ working directory ไม่ใช่โฟลเดอร์โปรแกรมจะหาโมเดลไม่เจอ → เปลี่ยนเป็น `resource_path(...)`
- **`.env` ใน `%APPDATA%\ResumeAI\` ไม่ถูกโหลด**: `llm_providers.py` เรียก `load_dotenv()` แบบไม่ระบุ path (หา `.env` ใกล้ตัวโค้ด/working directory) ส่วน `launcher.py` แค่เขียนไฟล์แต่ไม่โหลด → key ที่บันทึกไว้อาจไม่ถูกใช้หลังเปิดโปรแกรมใหม่
  - แก้: ตอนเริ่มโปรแกรม (ก่อน import อะไรที่อ่าน key) โหลด `get_writable_config_path()` แบบระบุ path ชัดเจน
  - ตอนรันแบบ dev ยังอ่าน `.env` ในโฟลเดอร์โปรเจกต์ได้เหมือนเดิม
  - ทดสอบ: บันทึก key → ปิด exe → เปิดใหม่ → วิเคราะห์ได้โดยไม่ต้องใส่ key ซ้ำ
- **Tesseract ไม่ถูกตั้ง path ที่ไหนเลย** (ไม่มี `tesseract_cmd`) → แก้ในหัวข้อ 4
- **`requirements.txt`**:
  - `dotenv` → `python-dotenv` (Dockerfile ต้อง pip install `python-dotenv` เพิ่มเองเพราะเรื่องนี้)
  - เพิ่ม `python-multipart`, `pystray`, `ngrok`
  - แยกของที่ใช้แค่ตอน build (`pyinstaller`) ไปไว้ `requirements-build.txt`
  - ทำ `requirements-lock.txt` (pin เวอร์ชันจาก venv ที่ใช้ build จริง) ให้ build exe ซ้ำได้ผลเหมือนเดิม
- README ยังบอกว่าเปิดครั้งแรกจะมีหน้าต่าง tkinter ให้กรอก key → อัปเดตให้ตรงกับของใหม่

## 3. ประสบการณ์ใช้งานของอาจารย์

### 3.1 เปิดโปรแกรมครั้งแรก
- ภายใน ~2 วินาทีหลังดับเบิลคลิกต้องมีอะไรขึ้นให้เห็น (splash หรือแจ้งเตือนที่ tray) — โมเดลโหลดเกือบ 1 นาที ถ้าเงียบนานอาจารย์จะกดเปิดซ้ำ
- พร้อมแล้วเปิดเบราว์เซอร์เอง ถ้ายังไม่มี key ให้ไปหน้า **ตั้งค่าครั้งแรก** ทีละขั้น:
  1. เลือกค่าย AI (Gemini ถูกเลือกไว้ก่อน มีป้าย "แนะนำ")
  2. วาง key → ตรวจสอบ (มีลิงก์ไปหน้าขอ key ของค่ายนั้น + คำอธิบายภาษาไทย 2–3 บรรทัด เช่น Gemini: aistudio.google.com/apikey)
  3. เลือกโมเดล (★ แนะนำ ถูกเลือกไว้ก่อน) → บันทึก → ไปหน้าวิเคราะห์
- เปิด exe ซ้ำตอนที่ตัวแรกยังรันอยู่ → เปิดเบราว์เซอร์ให้เฉยๆ ไม่ error (รอบ 1 ทำแล้ว ให้เช็คว่ายังทำงานหลัง merge)

### 3.2 หน้าวิเคราะห์ให้อ่านง่าย
- ผลหลักที่โชว์ก่อน:
  - คะแนนความเหมาะสม (`matching_score`)
  - คำแนะนำ ควรรับ/ไม่ควรรับ + เหตุผล (`recommendation_reason`)
  - ทักษะที่พบ (รวมที่อ่านจากกราฟิก)
  - จุดเด่นเทียบกับงาน (`specific_strengths`)
  - การเล่าเรื่องในเรซูเม่ (`storytelling_score`, `ai_reason`)
- ค่าทางเทคนิคพับไว้ใต้ "รายละเอียดเพิ่มเติม": `raw_matching_score`, `matching_penalty_multiplier`, `skill_overlap_ratio`, confidence ต่างๆ, provider + latency, วิธีสกัดข้อความ
- คำเตือน (`text_extraction_warning`) แสดงเป็นภาษาที่คนทั่วไปเข้าใจ เช่น "ไฟล์นี้อ่านตัวอักษรได้ไม่ครบ ระบบใช้การอ่านจากภาพแทน ผลอาจคลาดเคลื่อนเล็กน้อย"
- ปุ่ม **"ลองด้วยเรซูเม่ตัวอย่าง"**:
  - ใช้ PDF ตัวอย่าง 2–3 ไฟล์จาก `synthetic_resumes/` + รายละเอียดงานจาก `job_descriptions.json` แพ็กไปกับ exe
  - เลือกให้มีทั้งแบบเล่าเรื่องดีและแบบเขียนเป็นรายการคำ เพื่อให้เห็นผลต่างกัน
  - อาจารย์จะได้ลองได้ทันทีโดยไม่ต้องหาไฟล์เอง
- ปุ่ม "คัดลอกผล" (ข้อความสรุป) ให้เอาไปวางที่อื่นได้
  [หมายเหตุ: ถ้ามีเวลาเหลือ เพิ่ม "บันทึกผลเป็น PDF" ด้วย `window.print()` + CSS สำหรับพิมพ์ ไม่ต้องใช้ library]

### 3.3 ข้อความ error เป็นภาษาไทยทั้งหมด
- ไม่มีอินเทอร์เน็ต
- key ใช้ไม่ได้
- โควตาเต็ม (429)
- โมเดลไม่มีแล้ว (404) → พาไปเปลี่ยนโมเดล
- ไฟล์ไม่ใช่ PDF / ใหญ่เกิน
- PDF อ่านไม่ได้เลย
- พอร์ตถูกโปรแกรมอื่นใช้อยู่
- ทุกข้อความบอกว่าต้องทำอะไรต่อ ห้ามโชว์ traceback ในหน้าเว็บ

### 3.4 tray, log, เวอร์ชัน
- เมนู tray ภาษาไทย: "เปิดหน้าเว็บ", "เปิดโฟลเดอร์ log", "ออก"
- เขียน log ลง `%APPDATA%\ResumeAI\logs\` แบบหมุนไฟล์ (เช่น `RotatingFileHandler` 5 ไฟล์ × 1 MB)
  - ปิดบัง key / token ใน log ทุกจุด
  - มีปัญหาแล้วอาจารย์ส่งไฟล์ log มาให้ดูได้
- แสดงเลขเวอร์ชันที่ท้ายหน้าเว็บและใน tooltip ของ tray (เช่น `v2.0.0`)

### 3.5 ส่วนเชื่อมกับเว็บ (งานรอบ 2)
- เก็บโค้ด ngrok / พอร์ต public / token ลับไว้ทั้งหมด ห้ามลบ
- ย้ายไปอยู่ในหัวข้อ "เชื่อมต่อกับเว็บไซต์ (ขั้นสูง)" ที่พับไว้ในหน้าตั้งค่า
- ปิดเป็นค่าเริ่มต้น ถ้ายังไม่ได้ใส่ ngrok authtoken ห้ามมีข้อความ error เกี่ยวกับ tunnel โผล่ขึ้นมา
- ตั้ง authtoken ล่วงหน้าบนเครื่องอาจารย์ได้ (ผู้ใช้จะใส่ authtoken ของตัวเองให้ตอนติดตั้ง)

## 4. แนบ Tesseract ไปกับโปรแกรม
- เครื่องอาจารย์น่าจะไม่มี Tesseract → เรซูเม่ภาษาไทยที่ทำจาก Canva จะใช้ OCR fallback ไม่ได้
- ใส่ในโฟลเดอร์ `tesseract/` ของ bundle:
  - `tesseract.exe` + DLL ที่ต้องใช้ (จาก build ของ UB-Mannheim)
  - `tessdata/tha.traineddata`, `tessdata/eng.traineddata` (และ `osd.traineddata` ถ้าจำเป็น)
- ตอนเริ่มโปรแกรม:
  - ตั้ง `pytesseract.pytesseract.tesseract_cmd` และ `TESSDATA_PREFIX` ผ่าน `resource_path()`
  - ถ้าไม่เจอโฟลเดอร์ที่แนบ (ตอนรันแบบ dev) ให้ใช้ Tesseract ของเครื่องตามเดิม
- ใส่ไฟล์ license ของ Tesseract (Apache 2.0) ไปด้วย
- ทดสอบบนเครื่องที่ไม่ได้ลง Tesseract ว่า OCR ทำงาน

## 5. ตัวติดตั้ง (Installer)
- ถ้ามีสคริปต์ตัวติดตั้งเดิมอยู่แล้ว (README อ้างถึง `ResumeAI_Setup.exe` ใน Releases, tag `v1.0.0`) ให้ต่อยอดจากของเดิม ถ้าไม่มีให้ใช้ **Inno Setup**
- PyInstaller แบบ **onedir** (ไม่ใช่ onefile — โมเดลรวมเกิน 1 GB ต้องแตกไฟล์ลง temp ใหม่ทุกครั้งที่เปิด)
- ตัวติดตั้ง:
  - **ไม่ต้องใช้สิทธิ์ admin** (`PrivilegesRequired=lowest`, ติดตั้งลง `{localappdata}\Programs\ResumeAI`) — เครื่องในมหาวิทยาลัยมักไม่ให้สิทธิ์ admin
  - สร้างไอคอน "Resume AI" บนเดสก์ท็อปและ Start Menu พร้อม shortcut "คู่มือการใช้งาน"
  - มีตัวถอนการติดตั้ง ตอนถอนให้ถามว่าจะลบการตั้งค่า (`%APPDATA%\ResumeAI`) ด้วยไหม
  - หน้าจอสุดท้ายมีตัวเลือก "เปิด Resume AI เลย"
- ลดขนาด:
  - ใช้ **PyTorch แบบ CPU-only** ตอน build (`--index-url https://download.pytorch.org/whl/cpu`) — แบบ CUDA ใหญ่หลาย GB และเครื่องอาจารย์ไม่ต้องใช้ GPU
  - ตัดแพ็กเกจที่ไม่ใช้ออกจาก bundle
  - [หมายเหตุ: เช็คว่า runtime ยังต้องใช้แพ็กเกจ `en_core_web_lg` แยกไหม หรือ `skill-extractor-model` ที่ save ไว้มี vectors ครบแล้ว ถ้าไม่ต้องใช้ให้ตัดออก]
- ขนาดเป้าหมาย: ไฟล์ติดตั้งแต่ละไฟล์ไม่เกิน 2 GB (ขีดจำกัดต่อไฟล์ของ GitHub Releases)
  [หมายเหตุ: ถ้าเกิน ใช้ `DiskSpanning` ของ Inno Setup แยกเป็นไฟล์ `.bin` — เช็ครายละเอียดใน docs ของ Inno Setup]
- exe ไม่ได้ sign → Windows SmartScreen จะเตือน "Windows protected your PC" ตอนเปิดครั้งแรก ต้องเขียนวิธีกดผ่านไว้ในคู่มือ (ไม่ต้องทำ code signing ในรอบนี้)

## 6. คู่มือการใช้งาน (ภาษาไทย)
- ทำ `คู่มือการใช้งาน.pdf` (หรือ HTML ที่เปิดในเบราว์เซอร์) ไม่เกิน 3–4 หน้า แพ็กไปกับตัวติดตั้ง + มีลิงก์ "วิธีใช้" ในหน้าเว็บ
- เนื้อหา:
  1. ติดตั้ง (รวมวิธีกดผ่านหน้าเตือน SmartScreen)
  2. ขอ Gemini API key (ทีละขั้น)
  3. ตั้งค่าครั้งแรก
  4. วิเคราะห์เรซูเม่ + อ่านผลแต่ละส่วนหมายความว่าอะไร
  5. เปลี่ยน key / เปลี่ยนโมเดล
  6. แก้ปัญหาที่พบบ่อย (เปิดไม่ขึ้น, key ใช้ไม่ได้, โควตาเต็ม, ผลภาษาไทยเพี้ยน) + วิธีส่ง log
- ใส่ช่องว่างสำหรับภาพหน้าจอ เป็น `[ภาพ: ...]` ให้ผู้ใช้ถ่ายใส่เองทีหลัง

## 7. เช็คลิสต์ทดสอบ (ทำบน exe ที่ build แล้วจริง)

### เครื่องสะอาด (Windows Sandbox หรือ VM ที่ไม่มี Python / Tesseract)
- [ ] ติดตั้งได้โดยไม่ขอสิทธิ์ admin, ขนาดไฟล์ติดตั้งไม่เกิน 2 GB
- [ ] ดับเบิลคลิกไอคอนบนเดสก์ท็อป → มีอะไรขึ้นให้เห็นภายใน ~2 วินาที → เบราว์เซอร์เปิดหน้าตั้งค่าครั้งแรก
- [ ] ตั้ง Gemini key + โมเดล → ปุ่ม "ลองด้วยเรซูเม่ตัวอย่าง" ได้ผลครบ
- [ ] ปิด exe → เปิดใหม่ → ไม่ต้องใส่ key ซ้ำ และวิเคราะห์ได้
- [ ] PDF ภาษาไทยจาก Canva → OCR fallback ทำงานด้วย Tesseract ที่แนบมา
- [ ] `synthetic_resumes/visual/A.pdf` → มี `visual_skills` แสดงในหน้าผลลัพธ์
- [ ] มีแค่ Claude หรือ OpenAI key (ไม่มี Gemini) → วิเคราะห์ได้ ส่วนอ่านสกิลจากกราฟิกถูกข้ามพร้อมข้อความอธิบาย
- [ ] ถอดสายเน็ต → ข้อความภาษาไทยบอกว่าไม่มีอินเทอร์เน็ต
- [ ] ถอนการติดตั้ง → ไฟล์โปรแกรมหายหมด และถามเรื่องลบการตั้งค่า

### ของเดิมต้องไม่เสีย
- [ ] `/analyze` ด้วย `resume_url` (แบบที่ backend Node.js เรียก) ได้ผลครบ รวม field ใหม่ `visual_skills`
